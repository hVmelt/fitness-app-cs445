# Development Process

## Chosen Model: Agile (Scrum)

Our team is using an **Agile process based on Scrum** to build our diet and fitness web application.

## Why Scrum

- Our requirements are not fully defined and are expected to change as we build and test the app.
- Work is split into short sprints, each producing a working, tested increment.
- Features that depend on each other (e.g., calorie goal → remaining calories) are ordered in the backlog and tested as they're built.
- Design decisions, especially UI, can be adjusted based on team feedback after each sprint.

## How We Apply It

- **Backlog:** Managed on our GitHub Projects board (`Backlog`, `In Progress`, `Done`), with user stories linked to GitHub Issues.
- **Sprints:** Short iterations focused on a small set of features, starting with user input, maintenance calorie calculation, and database setup.
- **Check-ins:** Short, regular team check-ins instead of formal daily stand-ups.
- **Product owner:** The team prioritizes the backlog together, since there is no external customer.
- **Scope control:** New feature ideas go into the backlog and are prioritized so they don't delay core functionality.
- **Refactoring:** Time is set aside periodically to keep the codebase clean as features are added.
